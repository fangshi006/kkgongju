# 坤坤工具箱 · 项目构想

> 最后更新：2026-10-19（v1.0 已完成开发并通过验证，见第 10 节）
> 本文档随讨论持续更新，是后续开发的唯一参考依据。

## 1. 一句话概括

把 U 盘里长期收藏的实用工具，做成一个**部署在线上、可浏览阅读**的静态网站，用来向别人介绍和分享这些工具。

- **站点名称：坤坤工具箱**
- **副标题：精选软件，每个都有用**
- **技术形态：纯静态单页网站，零依赖、零构建**

## 2. 背景与使用场景

- 收集了一批自己觉得好用的工具，放在 U 盘里。
- 直接把 U 盘递给别人，对方不知道里面每个工具是干什么的、该用哪个。
- 因此需要一个"工具目录 + 介绍"的网页，代替口述介绍，别人打开网址就能自己看。
- 网站本身是**只读的**：不需要登录、不需要账号，复制网址到浏览器打开即可浏览。

## 3. 已确定的决策

| 编号 | 决策 | 说明与理由 |
| --- | --- | --- |
| D1 | 网站定位为"只提供浏览阅读" | 不做工具运行、不做后台管理、不做用户系统 |
| D2 | 部署到线上访问 | 别人通过网址浏览，不依赖插 U 盘；网站是"介绍层"，不承载工具文件 |
| D3 | 页面纯介绍，不标注工具在 U 盘中的路径，也不提供文件下载 | 保持页面干净，避免暴露本地目录结构；工具本体的传递走线下 |
| D4 | 技术方案：纯静态、零依赖 | 手写 HTML/CSS/JS，不引入构建工具、不依赖 CDN |
| D5 | 内容规模：几十个工具，手写清单维护 | 用一个数据文件登记条目，改内容只改这一处 |
| D6 | 视觉主题：跟随系统深浅色，并提供手动切换 | 见第 4 节 |
| D7 | 页面结构：单页 + 卡片列表 + 就地展开详情 | 全站只有一个 HTML，不跳页、不弹窗 |
| D8 | 首页功能：搜索框 + 分类筛选 + 手动主题切换 | 不做标签、不做排序 |
| D9 | 手机访问也要好用 | 卡片网格在窄屏自动变单列，触控目标尺寸、字体、间距按手机调整 |
| D10 | 起步方式：先用 6~8 条样例数据跑通 | 之后替换成真实工具，增量补内容 |
| D11 | 托管平台暂不绑定 | 全部使用相对路径，最终做成一个可直接丢到任意静态服务器的文件夹；网址以后再说 |
| D12 | 只用"分类"一套归类体系，不做标签 | 分类固定 7 类：系统工具 / 办公效率 / 影音图像 / 开发编程 / 网络工具 / 安全维护 / 其他 |
| D13 | 展示字段：名称、一句话简介、长介绍、官网链接、分类 | 长介绍在卡片展开后显示 |
| D14 | 站点名称：坤坤工具箱 | — |
| D15 | 第一个样例工具：PDF Gear | 一句话简介："文件格式免费转换" |
| D16 | 卡片视觉标识：首字色块 | 取名称首字，背景色由名称哈希生成，零素材成本 |
| D17 | 副标题：精选软件，每个都有用 | — |
| D18 | 长介绍口吻：客观描述功能 | 平铺直叙说清功能和使用场景，不带主观评价 |

## 4. 主题切换设计

- 默认跟随系统（`prefers-color-scheme`）。
- 手动切换按钮点击循环：**跟随系统 → 浅色 → 深色**。
- 手动选择写入 `localStorage`（键名 `kk-theme`），下次打开记住；选"跟随系统"时清除记忆。
- 页面 `<html>` 上落地 `data-theme="light|dark"` 与 `data-mode="system|light|dark"`：前者驱动配色，后者驱动按钮图标。
- 首屏在 `<head>` 内用一小段内联脚本先算出主题，避免刷新时闪一下浅色。

## 5. 界面构想（单页，自上而下）

1. **头部**：大标题"坤坤工具箱" + 副标题 + 右侧主题切换按钮。
2. **搜索框**：按关键词即时过滤（范围：名称、简介、长介绍）。
3. **分类导航**：一行横向 chips —— `全部 / 系统工具 / 办公效率 / 影音图像 / 开发编程 / 网络工具 / 安全维护 / 其他`，单选，与搜索词叠加生效。
4. **计数**：无筛选显示"共 N 个工具"，有筛选显示"找到 N 个工具"。
5. **卡片网格**：见第 6 节。桌面 3 列、平板 2 列、手机 1 列。
6. **空状态**：无结果时给提示 + "清空筛选"按钮。
7. **页脚**：最后更新时间。

## 6. 卡片与展开形态

- **收起态**：左侧首字色块 + 名称 + 分类小字 + 一句话简介（2 行截断）+ "展开"按钮。
- **展开态**（就地展开，不跳页、不弹窗）：按钮下方追加长介绍段落 + "访问官网 ↗"按钮。
- 同一时间允许多张卡片展开；展开状态不写入 localStorage。
- 官网链接在新标签页打开（`target="_blank" rel="noopener noreferrer"`）；没有链接时展开区自动省略该按钮。

## 7. 内容模型

```jsonc
{
  "name": "PDF Gear",
  "desc": "文件格式免费转换",
  "detail": "支持 PDF 与 Word、Excel、PPT、图片之间的相互转换，另带压缩、合并、拆分和 OCR 识别功能。基础功能免费，界面提供中文，适合日常处理文档格式转换的场景。",
  "url": "https://www.pdfgear.com/",
  "category": "办公效率"
}
```

- `category` 必须属于第 3 节 D12 的 7 个分类之一。
- `detail` 建议 2~4 句（约 60~120 字），客观描述功能与适用场景。
- `url` 可留空；为空时展开区不显示官网按钮。

## 8. 数据与文件结构

```
坤坤工具箱/
├── index.html          # 页面骨架
├── style.css           # 样式（含深浅色变量）
├── app.js              # 渲染、搜索、筛选、展开、主题切换
├── data.js             # 工具清单：window.TOOLS = [...]
├── docs/项目构想.md    # 本文档
├── docs/screenshots/   # 效果预览图（仅文档用，可不部署）
└── README.md           # 怎么改内容、怎么部署
```

> 选择 `data.js` 而不是 `data.json`：双击 `index.html` 用 `file://` 打开时，`fetch` 读 JSON 会被浏览器安全策略拦截，而 `<script>` 引入 JS 不会。线上部署时两者都可用。

## 9. 明确的非目标

- 不做工具在线运行或云端使用
- 不在页面中提供工具文件下载或本地路径指引
- 不做用户注册、评论、收藏等社区功能
- 不做内容管理系统（CMS）
- 不做标签体系、不做排序功能
- 不做每工具独立页面、不做 URL 路由
- 不做搜索引擎优化（暂不处理 SEO 与分享预览）
